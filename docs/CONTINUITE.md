# Continuité de projet — TRANSORA

## Référence permanente
Ce document garantit qu'un nouvel agent peut reprendre le projet sans dépendre d'une conversation précédente.

## Hiérarchie
1. Décisions validées
2. Cahier des charges maître
3. Architecture validée
4. Roadmap
5. Documentation technique de l'existant
6. Tâches et commits.

## État initial
Le dépôt a été créé et la documentation fondatrice doit être considérée comme la référence avant tout développement.

## Méthode
Ne jamais déduire qu'une fonctionnalité existe parce qu'elle est décrite. Vérifier le code.

Ne jamais considérer une implémentation comme conforme sans tests adaptés.

## Transfert
Tout agent entrant doit :
- lire la documentation
- auditer l'état courant
- identifier les changements récents
- vérifier les tests
- reprendre uniquement une tâche explicitement définie.

## Journal de session
À chaque étape importante, documenter : objectif, état avant, changements, tests, risques, décisions en attente.
